# Changelog

## 3.5.4 — 2026-08-10

- Исправлен ложный успех in-app update: новая версия принимается только после отдельного readback установленного payload, Automatic/LocalSystem Core-службы и полного удаления transaction state.
- Удаление старого service/network backup теперь fail-closed: ACL или locked-file ошибка запускает безопасный rollback вместо скрытого продолжения.
- Проверка Core работает из обычного пользовательского сеанса: named-pipe PID сверяется с SCM PID и защищённым `QueryServiceConfig`, без доступа `OpenProcess` к LocalSystem-процессу.
- Менеджеры DNS/DoH, Telegram Proxy и Запрет больше не фиксируют временную недоступность Core на весь сеанс после гонки запуска updater.
- Ошибка DNS отдельно сообщает о недоступной системной службе, не маскируя её под права администратора или отсутствие адаптера.

## 3.5.3 — 2026-08-10

- Исправлена потеря `EgoistShieldTelegramProxy` после успешного обновления: установленная Automatic-служба теперь переносится в новую версию транзакционно.
- Setup сохраняет только подтверждённую каноническую службу `LocalSystem`, заменяет runtime и WinSW wrapper байтами нового пакета и повторно проверяет `Start=2`, недопустимость delayed start, dependencies и failure recovery.
- Если служба работала до обновления, установка завершается только после SCM `Running` и готовности локального порта; при ошибке возвращается предыдущая версия вместе с её службой.
- Статус службы больше не зависит от WMI/CIM: приложение использует Core ServiceController и locale-neutral `Get-Service` fallback, поэтому работающая служба не отображается как `unknown` на системах с недоступным WMI.
- Исправлено восстановление ACL транзакционных файлов чистой установки: Setup проверяет каждый разрешённый файл через .NET ACL API и не принимает частичный `icacls /C` как успех.
- Чистая установка и явно удалённая пользователем служба остаются выключенными до нажатия «Установить фоновую службу».
- Добавлен реальный in-place Sandbox regression: service install → повторный Setup → SCM/runtime readback до повторного запуска приложения.

## 3.5.2 — 2026-08-09

- Исправлен статус DNS «Работает без приложения»: нативный Windows DoH и DNS адаптера больше не считаются зависимыми от Electron-процесса, а локальный resolver честно требует работающую службу.
- Устранена утечка native token handle при повторных подключениях к Core named pipe; добавлен 120-кратный regression gate.
- Ожидаемая отмена проигравших route probes больше не записывается как ошибка после успешного выбора маршрута.
- Убраны лишние idle-анимации, исправлена busy-progress анимация и нормализованы узкие/200%-scaled компоновки без изменения структуры экранов.
- Установщик, manifest schema v2 и updater trust chain сохранены; `v3.5.0` и `v3.5.1` остаются неизменяемыми.

## 3.5.1 — 2026-08-09

- Исправлена комплектация установленного приложения: root public key и подписанный registry доверенных release keys теперь входят в `resources/release`.
- Package gates сверяют все trust-файлы с исходными байт-в-байт и блокируют сборку при отсутствии любого из них.
- Уведомления о результате действий больше не перекрывают интерфейс постоянно: успех скрывается через 2,4 с, предупреждение через 6 с, ошибка через 8 с; любое уведомление можно закрыть вручную.
- `v3.5.0` и его assets не изменялись; исправление выпущено отдельной immutable patch-версией.

## 3.5.0 — 2026-08-09

- Канонический публичный updater channel перенесён на `egoist-ai1/egoistshield`.
- Добавлена атомарная операция check → download → verify → install → restart.
- Manifest schema v2 подписывает точные UTF-8 bytes branded Setup.
- Добавлены key registry/revocation, anti-rollback, `.partial` resume и TOCTOU recheck.
- Сетевые, HTTP 404 и trust-ошибки больше не отображаются как «версия актуальна».
- Setup перезапускает новую версию после commit и восстановленную версию после rollback.
- Интерфейс показывает реальную фазу и процент без raw HTTP/.NET/PowerShell текста.

Старые релизы до 3.5.0 считаются legacy и не участвуют в доверенном one-click channel.
